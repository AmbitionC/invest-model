# 策略研究流程 SOP（owner 2026-08-02 确立）

> 适用范围：任何触及买卖规则、仓位、信号、参数的策略变更。
> 原则：**这是一流投资系统的研究流程，不是试参数。任何一步跳过，结论作废。**

## 七步流程

### 1. 命题与判据预登记（跑数之前）
- 用一句话写清命题（要改什么、为什么认为它更好）。
- **判据先写死**：过关线、评估窗口、资金口径、必报指标、稳健性要求，全部落到 `docs/model_change_proposals.md` 的 E 序号段并提交。
- 判据一旦登记，**跑数过程中不得修改**。为让某个历史事件过关而回调阈值＝p-hacking 红线。

### 2. 数据拉取与校准
- 数据来源、起止、行数、缺口全部核验并记录。
- 必做：交易日对齐、缺失/重复/异常值扫描、与独立源抽样对账。
- 数据问题的影响量级必须量化，不能只说"有个小缺口"。

### 3. 质疑数据（不是走过场）
- 问三件事：这个字段的口径是什么？它在决策时点真的可得吗（前视偏差）？它在极端行情下会不会反向失效？
- 已有教训：两融比在崩盘底反向飙升；红利价格锚因指数趋势上行而永久失效；恐慌指数是收盘后才可得。

### 4. 独立 Agent 并行设计与验证
- 至少 **2 个设计 Agent**（不同技术路线，互不知晓对方方案）+ **1 个红队 Agent**（只负责挑错：复算关键结论、审前视偏差、评估过拟合与选择性偏差、检验口径陷阱）。
- 每个 Agent 交付：可复现脚本 + 结论 Markdown + **失败方案清单**。
- Agent 必须被明确要求"如实报告达不到目标"，负结果与正结果同等对待。

### 5. 交叉核对与裁决
- 主线（我）独立跑一份基线，与 Agent 结果对账；数字对不上必须定位到口径差异或 bug，不允许含糊带过。
- 红队提出的问题逐条回应：确认 / 部分确认并修正 / 有证据地驳回。
- 对照判据逐条判定过关与否，**不满足即不上线**，负结果入库。

### 6. 图表与指标
必报（缺一不可）：
- 年化收益、年化波动、**夏普比（无风险利率 2%）**、最大回撤、卡玛比（年化/最大回撤）
- 买入/卖出次数与年均频次、平均持仓占比（现金拖累）
- 分半段（前半/后半）结果 —— 符号翻转即判不稳健
- 图：净值曲线 + 回撤带、买卖点位标注在价格图上、与基线（买入持有/定投）对照

### 7. 汇报
- 先给结论与判据判定，再给数字，最后给图。
- 明确标注置信度（强 / 中 / 弱），弱证据（如 n=1 个市场周期）必须显式说明外部效度局限。
- 明确说明"我建议做什么"和"需要 owner 决策什么"。

## 口径约定（除非命题另有说明）

- 资金：一笔钱 100 元投入、无追加；闲置现金按 2%/年计息。追加口径（月度定额）作为敏感性对照，两者结论若排序翻转必须报告。
- 无风险利率：2%（夏普计算用）。
- 回测窗口：各腿以锚预热完成日为起点，统一终点为最新交易日。
- 复现脚本一律只读 dump 文件、不连生产库、不联网。

## 规格必填项增补（2026-08-03·M1 多触发器竞争）

来源：life-teachers `topics/investing.md`「仓位与容错体系」第六节。陈老师的真实决策是
**同时持有多条独立触发条件、谁先触发用谁**，而不是单规则串行执行。

> **逐条独立回测会系统性误估这类方法**——真实执行中一条规则常被另一条抢先触发并消耗掉资金/额度。

**因此，凡涉及「多条买入腿并存」或「多条卖出腿并存」的提案，验证必须同时报告两组结果：**

| 口径 | 定义 |
|---|---|
| **独立口径** | 每条腿各自独立回测，互不影响（现行做法） |
| **竞争口径** | 所有腿共享同一资金池；先触发者先消耗，后触发者只能用剩余额度 |

**两者结论不一致时以竞争口径为准。** 本仓 2026-08 前已跑的 E31/E35/E36/E37 与已登记的
E38/E39/E40/E42/E43 均为独立口径，重跑或首评时须补竞争口径。
