## 🔴 先记两条**流程本身的失败**（比 diff 结果更重要）

SOP §7.8 是 2026-08-06 当天上午写的，**当天下午第一次执行就暴露两个实现缺陷**：

### 缺陷一：信息隔离被工具链单方面破坏，且我无法阻止

S 位在交付时**主动披露**：三个仓的 `CLAUDE.md` 全文被**自动注入**它的系统提示，非它主动读取。
而 `CLAUDE.md` 里写满了 P39/E37/E56/E57/E58/E59 的编号、失败机制与点估计——
**正是 S 位被要求看不到的东西。**

⟹ **§7.8 写的「输入只有原文、禁止看 P/E 文档」在当前工具链下无法通过 prompt 约束实现。**
S 位自称"撰写时刻意不引用任何编号提案与点估计"，从产物看确实做到了（它对 E56/E57 的
结论只字未提，且独立推导出的失败点与库内已有结论**形式不同**）——但这是**自律，不是隔离**，
证据力必须相应打折。

**修订**：§7.8 增两条——
1. **S 位必须在产物开头做注入披露**（本次它自己做到了，应写成硬性要求而非运气）；
2. **「S 与主线一致」不再算作独立证据；只有「S 与主线**不一致**」才有效力**（不一致不可能
   由污染产生——污染只会让它更像主线）。本次 diff 恰好全部价值都在不一致项上，这条可行。

### 缺陷二：时序证明失败（我自己的操作错误）

§7.8 要求主线规格先提交、S 位产物后落库，用 git 顺序证明双方未互相锚定。**实际执行失败**：

文件落在了仓库外；而 S 位产物 **11:03:03** 落盘、我的主线规格 **11:06:22** 落盘——
**S 的先落盘。**

我没有读过 S 的文件（主线规格的正文在收到 S 的通知**之前**就已写完发出，会话记录可查），
但这正是 §7.8 要避免依赖的那种**不可证伪的自我声明**。

**修订**：§7.8 增第 3 条——**主线规格必须在 spawn S 位之前就 commit 并 push**，
不能等 S 位在跑的时候再写。这才是真正的时序保证；本次的顺序（先 spawn、后写）
即使 commit 成功也只能证明"我写完了"，不能证明"我没看"。

## 一、两份规格一致的部分（因污染风险，**不作为证据**）

- 被交易的对象是**价格**，不是 bias；账户只能通过价格头寸间接下注 bias 的回归。
- 恒等式 `r_total = r_anchor + r_conv` 是全部推理的地基，必须逐笔分解、不能只报总收益。
- 出场绑定在**指标回到中枢**（而非等反向极值），这是与 E59 的关键差别。
- 高尾腿不做空（或降级为减仓），A 股宽基做空对本账户不可行。
- 三条从未参与调参的对照指数单列。
- 「近十年触发频次门」必须有。

## 三、🔴 实质分歧一项：「极值」用什么口径

| | M（主线） | S（校准位） |
|---|---|---|
| 主口径 | expanding **分位** X ∈ {2%, 5%, 10%} | **z 分数** `z=(bias−μ)/σ`（expanding），`Z_in=2.0`，网格 {1.5,2,2.5,3} |
| 对照臂 | 排名 | 分位作对照臂 X3 |

**S 的理由（三条，我认为成立）**：
1. 七腿 bias 的波动幅度差一倍以上（标准差 7.95%~10.20%），**同一分位阈值跨腿不可比**，
   汇总成「几腿达标」时会系统性偏向波动大的腿；
2. 分位口径在稀疏尾部极不稳（第 1% 分位由个位数样本决定）；
3. 排名口径会**永久锁死**（E57/E58/E59 三次的共同否决理由）。

**处置：采纳 S 的 z 分数为主口径，分位降为对照臂**，并采纳 S 提的那条检验——
**报「两口径触发日重合率」，若 <70% 则说明「什么叫极值」这个实现选择本身在决定结论，
必须并列呈现两套结果**（这正是 SOP §7.5 第 5 条）。

## 四、M 独有、S 结构上不可能发现的一项

**恐慌分不是独立于乖离率的信息源**——它 5 个等权分量里 ①动量 = 沪深300 距 MA125 的
**乖离率本身**、②波动率 = 同一条价格序列的函数。⟹ 直接拿 bias60 与恐慌合成分求相关，
**2/5 是定义带来的**。

S 看不到这一条，因为它被禁止读代码（`invest_model/signals/fear.py`）。
**这说明 S 位的隔离是有代价的**：它换来了对"题目"的独立判读，但同时切断了对"实现细节"的
访问，而有些决定性事实只存在于实现里。

⟹ **§7.8 再补一条**：S 位的产物**不能替代**主线对实现的核查，两者是互补不是替代；
凡涉及"某个输入变量是怎么造出来的"，一律由主线负责，S 位不承担。
